INICIO

Primero entiende qué estás construyendo

BancoNova es un simulador que se ejecuta en el navegador. El HTML contiene las pantallas, el CSS les da presentación y JavaScript procesa las operaciones. Los usuarios y sus movimientos se guardan en ese navegador.

Abre la carpeta completa en Visual Studio Code y ejecuta index.html con Live Server. Para consultar esta guía dentro del proyecto, abre documentacion/GUIA_DE_ESTUDIO.html. Conserva la misma dirección y puerto mientras practicas.

No tienes que entender todos los archivos el primer día. Primero registra un usuario, crea una compra llamada “Cuaderno”, consulta su plan y paga una cuota. Luego estudia el código que produjo cada resultado.

Practica en una copia y con datos ficticios. El proyecto usa saldos iniciales de ejercicio y guarda las claves como texto. La ruta explica esta limitación; no equivale a una banca real.

Los demás archivos

style.css contiene la presentación común, la paleta definida en :root y las reglas para distintos anchos de pantalla. LEEME.txt es la guía rápida de uso. documentacion/GUIA_DE_ESTUDIO.html es este material de aprendizaje; su laboratorio usa una clave propia, distinta a las del cajero.

En style.css, si dos reglas del mismo nivel afectan la misma propiedad, la que aparece después puede reemplazar a la anterior. El bloque final de acabado visual ajusta componentes ya definidos; las variables de la paleta en :root se mantienen.

El menú y la cabecera aparecen escritos en varios HTML. Es una decisión sencilla para este nivel: no hay un motor de plantillas ni componentes que los inserten automáticamente.

RECORRIDOS

Sigue una operación de principio a fin

Recorrido 1 · Registrar y entrar

  1. El usuario completa registro.html y envía el formulario.
  2. registrarUsuario() llama preventDefault(), lee los value y revisa datos y duplicados.
  3. crearUsuario() devuelve un objeto; usuarios.push(...) lo incorpora al arreglo.
  4. guardarUsuarios() serializa el arreglo completo.
  5. Se abre auth.html. iniciarSesion() busca al usuario y compara la clave.
  6. Si coincide, guarda solo el nombre en nova_sencillo_sesion y abre dashboard.html.

Esta es la función real de guardado:

function guardarUsuarios() {
  localStorage.setItem('nova_sencillo_usuarios', JSON.stringify(usuarios));
}

Recorrido 2 · Crear y pagar una compra

  1. tarjeta.html recibe nombre, precio y cantidad de cuotas.
  2. comprar() valida el cupo y pide a crearPlan() el arreglo de cuotas.
  3. La compra se agrega a usuarioActual.compras; sincronizarDeuda() suma el capital pendiente.
  4. Se registra el movimiento y se guarda. actualizarTarjeta() vuelve a dibujar los datos.
  5. En pagos.html eliges una compra o el mínimo del periodo.
  6. pagar() revisa el saldo y pide confirmación. aplicarPagoCuotas() descuenta capital e interés, marca las cuotas pagadas y actualiza la deuda.
  7. El historial se guarda y los resúmenes se recalculan.

Recorrido 3 · Cambiar cuotas

ajustarCuotas() conserva las filas pagadas y reemplaza las pendientes por un plan del capital que falta. No crea otra compra ni cobra de nuevo el valor completo. El nuevo número de cuotas determina la nueva tasa del ejercicio.

Por qué cambiar usuarioActual también cambia usuarios

// Ejemplo didáctico de referencias en memoria:
let lista = [{ nombre: 'Ana', saldo: 100 }];
let persona = lista[0];
persona.saldo = 150;
console.log(lista[0].saldo); // 150

buscarUsuario() devuelve el objeto que está dentro del arreglo, no una copia. Por eso modificar usuarioActual afecta al mismo objeto que luego se serializa al guardar usuarios. Hasta que se llama guardarUsuarios(), ese cambio solo vive en memoria.

STORAGE

localStorage, explicado desde cero

1. Qué es y dónde vive

localStorage es una función del navegador para guardar pares de clave y valor de texto. Una clave funciona como el nombre de un cajón; el valor es lo que colocas dentro. No escribe directamente en script.js ni en el ZIP. [2]

Puede conservar datos entre sesiones normales del navegador y no tiene una caducidad automática por fecha. El usuario puede borrarlos; la navegación privada tiene otra duración. Guardado local no significa respaldo permanente ni sincronización con tu celular. [1]

2. Las dos claves reales de BancoNova

ClaveQué guardaCuándo se cambia
nova_sencillo_usuariosTexto JSON del arreglo de todos los usuarios. Cada usuario incluye saldos, compras, cuotas, perfil e historial.guardarUsuarios(), después de registro u operaciones que modifican datos.
nova_sencillo_sesionTexto simple con el nombre del usuario que inició sesión. No contiene el objeto completo.iniciarSesion() la crea y cerrar sesión la elimina.

“Sesión” es el nombre de esta clave del proyecto. No quiere decir que use sessionStorage: el código la guarda en localStorage, por lo que puede seguir existiendo al volver a abrir el navegador.

3. La API que debes aprender

InstrucciónResultadoEjemplo de práctica
setItem(clave, valor)Crea la clave o reemplaza su valor anterior.localStorage.setItem("estudio_nombre", "Ana");

removeItem(clave)Borra solo esa clave.localStorage.removeItem("estudio_nombre");
clear()Borra todas las claves de localStorage del origen actual, incluso las de otros ejercicios en ese origen.No lo uses para cerrar sesión ni en el laboratorio.

Referencia de estas operaciones: Storage [2]. El proyecto conserva a muchos usuarios dentro de una sola clave JSON, por eso un nuevo usuario no aumenta necesariamente localStorage.length.

4. Por qué hacen falta JSON.stringify y JSON.parse

Los objetos y arreglos de JavaScript no se almacenan como objetos vivos en localStorage. JSON.stringify() produce texto JSON para guardarlos. La serialización no es cifrado; el contenido sigue siendo legible. [8]

let producto = { nombre: 'Cuaderno', precio: 12000, pagado: false };
let texto = JSON.stringify(producto);
localStorage.setItem('estudio_producto', texto);

// Contenido guardado: texto con estructura JSON.
console.log(localStorage.getItem('estudio_producto'));

JSON.parse() interpreta un texto JSON válido y devuelve un valor de JavaScript. Así recuperas números y booleanos, además de objetos y arreglos. Un texto que no sea JSON válido produce un error. [7]

let guardado = localStorage.getItem('estudio_producto');
if (guardado !== null) {
  let recuperado = JSON.parse(guardado);
  console.log(recuperado.nombre); // Cuaderno
  console.log(recuperado.precio); // 12000, número
}

// Al terminar la práctica, borra únicamente esta clave:
localStorage.removeItem('estudio_producto');

Evita localStorage.setItem('producto', producto): un objeto común se convierte en texto como [object Object], y pierdes la estructura que querías conservar.

5. Leer las líneas reales de carga

let usuarios = JSON.parse(localStorage.getItem('nova_sencillo_usuarios'));
if (usuarios === null) {
  usuarios = [];
  guardarUsuarios();
}
  1. getItem busca la clave del arreglo guardado.
  2. JSON.parse reconstruye el arreglo.
  3. Si no existía, getItem devolvió null; en este caso JSON.parse(null) también da null.
  4. El if prepara un arreglo vacío y lo guarda. No crea una cuenta de demostración.

Si el texto guardado fue editado incorrectamente, el JSON puede fallar. Esta versión del cajero no incorpora recuperación automática de JSON corrupto; en el laboratorio se muestra cómo detectar el error sin borrar información.

6. Cambiar la memoria no guarda automáticamente

// En el cajero, con un usuario autenticado:
usuarioActual.ahorros = usuarioActual.ahorros + 1000;
// Hasta aquí: solo cambió el objeto de esta página.

guardarUsuarios();
// Ahora: se volvió a guardar el arreglo completo en localStorage.

La pantalla tampoco cambia sola: después hay que llamar a una función como actualizarSaldos(). Son tres pasos distintos: cambiar el dato, persistirlo y mostrarlo. Al abrir otra página, script.js vuelve a leer lo guardado.

7. Origen: por qué parece que desapareció tu usuario

El almacenamiento se separa por origen: protocolo, nombre del servidor y puerto. Las carpetas no crean otra separación dentro del mismo origen. Por eso dos proyectos servidos con el mismo origen pueden compartir claves; los prefijos del nombre ayudan a evitar choques. [11]

Dirección¿Comparte datos con http://127.0.0.1:5500/index.html?Motivo

http://127.0.0.1:5500/otra-carpeta/index.htmlSí.La carpeta cambia, el origen no.
http://127.0.0.1:5501/index.htmlNo.Otro puerto.

Con file:// el comportamiento no está definido de manera uniforme para todos los navegadores. Usa Live Server y mantén el mismo origen para este proyecto. [1]

9. Capacidad, velocidad y errores

El almacenamiento tiene límite. MDN documenta hasta unos 5 MiB para localStorage por origen; la configuración del navegador puede restringirlo. Una escritura que no puede completarse puede producir QuotaExceededError. El acceso también puede estar bloqueado por políticas de privacidad. [4] [1]

Las operaciones son síncronas: JavaScript espera a que terminen. Para un ejercicio pequeño es manejable; guardar grandes arreglos o imágenes en cada pulsación puede frenar la interfaz. Por eso aquí se guarda al completar una operación, no en cada campo que escribes. [3]

Un ejemplo de manejo de errores para estudiar, no una función ya incorporada al cajero:

function leerPractica() {
  try {
    let texto = localStorage.getItem('estudio_banconova_ejemplo');
    if (texto === null) return null;
    return JSON.parse(texto);
  } catch (error) {
    console.error('No fue posible leer los datos:', error);
    return null; // No borra la clave que falló.
  }
}

10. Seguridad: qué puede y qué no puede proteger

El usuario del navegador puede inspeccionar y modificar los valores. Los scripts que se ejecutan en el origen pueden acceder a ellos; un ataque de inyección de JavaScript puede exponerlos. No guardes contraseñas reales ni identificadores sensibles de sesión en localStorage. [10]

En este simulador, la clave local con el nombre de usuario permite elegir qué objeto mostrar; no prueba de forma segura la identidad de una persona. Cambiar una ruta con JavaScript no sustituye la autorización del servidor. Una aplicación bancaria real necesitaría backend, controles de acceso y un mecanismo de sesión adecuado.

textContent ayuda a presentar el nombre de una compra como texto en vez de interpretarlo como HTML. No convierte por sí mismo a localStorage en un sitio seguro para secretos.

11. Dos pestañas no se sincronizan solas en este código

Otra pestaña del mismo origen recibe el evento storage cuando cambia el almacenamiento. La pestaña que hizo la escritura no recibe ese evento por su propio cambio. [5]

// Ejemplo opcional para una práctica, no está en el cajero:
window.addEventListener('storage', function(evento) {
  if (evento.key === 'nova_sencillo_usuarios') {
    console.log('Otra pestaña cambió los usuarios guardados.');
  }
});

BancoNova lee usuarios al cargar cada página y luego trabaja con ese arreglo en memoria. No escucha ese evento ni resuelve escrituras simultáneas. Para estudiar sin sobrescribir cambios, realiza las operaciones en una sola pestaña y recarga antes de revisar datos modificados en otra.

12. Qué no viaja dentro del ZIP

El ZIP contiene el código y la documentación; los usuarios que registraste en el navegador no se incorporan al comprimir la carpeta. En otro equipo, otro perfil o un origen diferente tendrás otro almacenamiento. Cerrar sesión solo elimina la clave local de sesión; no borra compras ni usuarios.

RETOS

Cinco ejercicios para comprobar que lo entendiste

1. Guardas un objeto en una variable y cambias su precio. ¿Se actualiza localStorage?

No. Debes serializar y escribir otra vez con setItem, o llamar a guardarUsuarios() si modificaste el usuario del cajero.

2. Hay tres usuarios guardados. ¿localStorage.length debe valer tres?

No. El arreglo de usuarios ocupa una sola clave. length cuenta las claves del origen, incluidas otras prácticas que usen el mismo origen.

3. Pagas capital 40000 e interés 2000. ¿Cuánto sale de ahorros y cuánto cupo se libera?

Salen 42000 de ahorros y se libera cupo por 40000. El interés es un costo del pago, no una compra adicional financiada.

4. Dos productos tienen cuotas del mismo mes. Pagas solo uno. ¿Qué pasa con el mínimo?

Incluye las cuotas de ese mes que sigan pendientes. La siguiente cuota del producto recién pagado pertenece a otro mes y no se añade al mínimo actual.

5. Abres otra carpeta del proyecto en el mismo host y puerto. ¿Tendrá otro localStorage?

No por cambiar la carpeta. El almacenamiento depende del origen. Cambiar host, protocolo o puerto sí cambia el origen.

Un recorrido para explicarle el proyecto al profesor

  1. Presenta HTML como estructura, CSS como presentación y JS como lógica.
  2. Muestra cómo el submit llama una función y cómo se leen los campos.
  3. Encuentra usuarioActual dentro de usuarios.
  4. Demuestra un cambio de saldo y un movimiento.
  5. Señala JSON.stringify al guardar y JSON.parse al abrir otra pantalla.
  6. Demuestra que una cuota tiene capital, interés, fecha y estado.
  7. Recarga y comprueba la persistencia. Explica que sigue siendo un simulador local.
